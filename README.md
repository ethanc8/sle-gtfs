# CTrail Shore Line East GTFS

An unofficial GTFS feed for CTrail Shore Line East, covering the two
standing timetables effective 2026-03-29 and 2026-10-05 (through
2026-11-01) plus the 2026-10-10/11 Walk Bridge outage exception, built from
the PDFs in `sources/`.

See [`llm_notes/SPEC.md`](llm_notes/SPEC.md) for the full design and the
reasoning behind every non-obvious decision. See
[`UPDATING.md`](UPDATING.md) when CTrail publishes a new schedule PDF and
this feed needs to be brought up to date.

## Building

Requires [pixi](https://pixi.sh) (Python + pdfplumber + tesseract, from
conda-forge) and [cargo](https://www.rust-lang.org/tools/install) (the
optional validator).

```sh
make all      # test + build + validate
make build    # just build/gtfs/*.txt and build/sle-gtfs.zip
```

Other targets:

- `make test` — unit tests for grid/column detection, time parsing and
  midnight rollover, and the exception-calendar suppression logic; also
  runs extraction against every PDF in `sources/older_examples/` as a
  generalization regression test.
- `make render-pdfs` — render every source PDF page to PNG
  (`build/pdf-preview/`), for checking a cell in `extracted/*.csv` against
  the actual timetable by eye.
- `make extract-draft` — re-run PDF extraction into `extracted/*.draft.csv`
  (never overwrites the reviewed `extracted/*.csv` — see below).

## Repository layout

- `sources/` — raw inputs: the current timetable PDFs, the 2026-10-10/11
  outage notice, `sources/older_examples/` (independent older PDFs used as
  extraction regression tests, not part of the shipped calendar — see
  SPEC.md section 2.4/9), and the Amtrak/MNR GTFS feeds used once, by hand,
  as a coordinate source (never read at build time — see
  `gtfs_builder/config.toml`). Never modified by this pipeline.
- `gtfs_builder/config.toml` — everything about this feed that isn't
  mechanically extracted from a PDF: agency/route branding, the station
  list (with coordinates copied once from `sources/`), and the list of
  timetable revisions (which PDF, which day-type, which dates/date-range).
  Hand-editable; see `UPDATING.md`.
- `extracted/` — the timetables themselves, pulled from the PDFs and
  manually verified cell-by-cell against the rendered pages before being
  trusted.
- `gtfs_builder/` — the Python pipeline: PDF grid detection
  (`pdf_grid.py`), timetable + track-badge OCR extraction (`pdf_extract.py`),
  and the GTFS builder itself (`build_gtfs.py`).
- `validator/` — a small Rust crate (`gtfs-structures`) that round-trip-
  parses the built feed and checks referential integrity, stop-time
  ordering, and the exception/standing calendar-suppression invariant.
- `build/` — everything generated by `make` (gitignored): `build/gtfs/*.txt`
  (unzipped feed) and `build/sle-gtfs.zip` (the packaged artifact).

## Known limitations

- No `shapes.txt` — the consumer will run `pfaedle-rs` downstream to derive
  shapes from real track geometry.
- No `transfers.txt`.
- Calendar coverage ends 2026-11-01; no stance taken on Thanksgiving/
  Christmas service for this feed (though the extraction pipeline is
  regression-tested against last year's Thanksgiving/MLK PDFs — see
  `sources/older_examples/`).
